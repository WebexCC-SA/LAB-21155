    Install Gateway Connector

    Install the gateway connector on CUBE/Gateway

    Before you can add a gateway to Control Hub as a Managed gateway, you will need to install a connector application on your device.

    • Continuing on Workstation 1, minimize all applications on desktop. Open new Putty window and connect to Survivability Gateway at 198.18.133.226 over SSH.

    • Login with credentials admin/dCloud123!

    • Run the following command to start connector application installation.

    Note

    All the commands are that are required to configure Local Gateway are put in a text file called Wx12026 – LGW - Config.txt on workstation 1 Desktop folder. If you are having trouble copying these commands from this document due to formatting issues, you can copy those commands from this file to Putty. Right click on the file and click Edit with Notepad++.

    Configuration:

    tclsh https://binaries.webex.com/ManagedGatewayScriptProdStable/gateway_onboarding.tcl

    This command runs precondition check to validate requirements for CUBE like disk space etc., if successful then it prints Precondition check status: Passed. Then it downloads and runs connector installation script.

    • At the prompt to select external interface enter number 2 and press Enter.

    • Next, it will prompt you to enter DNS Server address, enter 198.18.133.1 and press Enter

    • Select N for Proxy required option & press Enter.

    • For the Connector IP address enter 198.18.133.200 & press Enter

    Note

    The Connector IP address must be in the same network as the interface chosen for external connectivity. It can be a private network address, but it must have HTTP access to the internet.

    • 198.18.133.226 – GigabitEthernet2 used to access the network

    • 198.18.133.200 - Connector IP, used by Managed GW connector

    • Enter Gateway username as admin and press Enter.

    • Enter dCloud123! For Gateway Password and Confirm Password.

    Note

    NOTE: These credentials are used by the connector to access the platform’s NETCONF interface. This is an example of the basic configuration which was configured on this IOS-XE platform for this to work. These commands are listed for information purpose only. They are already configured on the IOS-XE platform.

    aaa new-model
aaa authentication login default local 
aaa authorization console
aaa authorization exec default local
username admin privilege 15 secret dCloud123!

    The username and secret must match with what is being configured during this step.

    • It takes around 4 to 5 minutes for connector application installation and configuration with above values. Wait for the installation process to complete.

    • Once the installation & configuration process is completed It will show the interfaces and the application status as shown below. Once you verify all the interfaces are showing up as the status and the service status is RUNNING, enter q to quit configuration menu.

    • This completes installation of connector application on the gateway, now we can continue to add it to the Webex Control Hub.

    Enroll the IOS-XE gateway in the Webex Control Hub

    • Continuing on Workstation 1, minimize Putty and other applications. Go back browser tab where you have logged into Webex Control Hub. If the previous login timed out login as cholland@cbXXX.dc-YY.com.

    • On the Control hub page go to SERVICES > PSTN & Routing. On the PSTN & Routing page go to Gateway Configurations > Managed gateways tab. Click Add gateway.

    • It will bring up Add a managed gateway wizard. Check mark option to confirm that I have installed the management connector on the gateway and click Next.

    • On the following page enter the following information and click Next.

    • Connector IP address: 198.18.133.200

    • Display name: sgw

    • It will open a new browser tab to the connector IP address (Survivability Gateway). Click Advanced and Proceed to 198.18.133.200 on the new tab. It will take you to login page, login as admin and dCloud123! (same credentials we configured that we configured during connection application installation)

    • Once logged in click Enroll Now on the Gateway Connector Management page.

    • If it will take you to Webex Control Hub login page. Login as cholland@cbXXX.dc-YY.com

    • Once Control Hub credentials are entered, on the Allow Access to Gateway Management Connector page, check mark option to Allow Access to Gateway Management Connector and click Continue.

    • The enrollment of the gateway to Webex Control Hub should be successful. You can close this browser tab now.

    • Now open a new browser tab and go to https://198.18.133.200 (The Connector IP address) and login as admin and dCloud123! (if prompted). It will install two services Management Connector and Telemetry Connector; the status of the services would change from installing to Connected once the installation is complete. This process takes a few minutes.

    • Go back to browser tab where the Webex Control Hub is logged in. Go to SERVICES > Calling > PSTN & Routing > Gateway Configurations > Managed gateways (if you are already on that page, click page refresh/reload). Verify that Connection Status for the gateway shows Online.

    • Click three dots, towards right side and select Assign Service.

    • It will bring up Assign Service to sgw wizard. Configure the following parameters and click Assign.

    • Drop down option for Webex Calling Service and select Survivability gateway

    • Drop down option for Location and select dCloud

    • Enter the Host Name as cube.cbXXX.dc-YY.com (replace cbXXX.dc-YY.com - this is the same domain from Charles Holland email domain portion)

    • Enter the IP Address as 198.18.133.226 (GigabitEthernet2)

    • The Gateway will be assigned with Service (Survivability Gateway) & location (dCloud) as shown below.

    • Click on the gateway sgw and on the gateway page click Download config template to download the configuration template that can be used to configure the Survivability Gateway.

    Note

    You can review the downloaded configuration template however in this lab the configuration steps/commands are already provided on Workstation 1 for easy access and use.
